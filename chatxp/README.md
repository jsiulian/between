# chatxp — Between for .NET

Cross-platform (.NET 10 / Avalonia) port of **[Between]**, the end-to-end encrypted,
peer-to-peer chat app originally written in SwiftUI + WebRTC.

Messages travel directly between devices over a WebRTC data channel. The signaling
server brokers only the initial handshake and never sees message content.

## Status

Core stack complete and tested (27/27):

- ✅ **E2EE crypto byte-identical to the iOS app** — P-256 ECDH + HKDF-SHA256 +
  AES-256-GCM, verified against CryptoKit-generated test vectors in both directions
  (`chatxp.Core.Tests/CryptoVectorTests.cs`). The iOS app and this port can chat.
- ✅ **Signaling client** for the existing Node.js server (`../server/index.js`) —
  verified against the real server (register, offer/answer/candidate relay, `not_found`,
  `reject`).
- ✅ **WebRTC manager** (SIPSorcery — pure C#, no native deps): connect/accept/reject,
  trickle ICE, 15s timeout, drop signaling once P2P, typed `Event` send queue.
- ✅ **SQLite persistence** — messages (encrypted at rest), contacts, blocked users,
  conversation + history queries mirroring the SwiftData screens.
- ✅ **Avalonia UI** — Connect (peer id + incoming accept/reject), Chat (bubbles,
  typing indicator, send), status footer.
- 🚫 **Voice calls** — deferred; see `business-requirements.md` § 5.1 (Todo).

## Run

```bash
# 1. signaling server (unchanged Node.js app)
cd ../server && npm install && npm start 3000

# 2. desktop app
dotnet run --project chatxp.App
```

The app registers on `ws://150.230.37.157:3030/` by default. Change the server in the
app: **Connect tab → Signaling server → Apply** (persisted across restarts), or set the
`CHATXP_SIGNAL_SERVER` environment variable (env overrides the saved setting).

Two copies of the app (or one copy + the iOS app) can chat by exchanging their IDs
(the Base64 public key shown in the header; click to copy) out of band.

## Notes

- **WebRTC choice**: SIPSorcery 10.0.17 — pure-managed (works on macOS arm64 /
  Windows / Linux with no native binaries). The originally-planned `WebRTC.Client`
  NuGet does not exist; see PROGRESS.md.
- **Key storage (v1)**: identity key is a PKCS#8 file under the OS app-data dir with
  user-only permissions. Hardware-backed storage (Secure Enclave equivalent) is out
  of scope — documented in `business-requirements.md` NFR-3.
- **Identity format**: Base64 of CryptoKit `rawRepresentation` (64 bytes `X‖Y`) —
  identical string to the iOS app's "public key".
